# Pulse Messenger

Pulse Messenger — мой self-hosted мессенджер для небольших команд и закрытых сообществ. Проект появился как внутренняя система общения, а со временем вырос в полноценное веб-приложение с личными чатами, комнатами, файлами, опросами и административной частью.

Это не попытка заменить Telegram или Discord. Основная идея проекта — дать организации возможность развернуть собственный мессенджер на своём сервере и самостоятельно управлять пользователями и данными.

## Что уже работает

- регистрация и авторизация пользователей;
- личные сообщения и групповые комнаты;
- обмен сообщениями в реальном времени через Socket.IO;
- реакции, ответы и статусы прочтения;
- загрузка изображений, видео и документов;
- опросы;
- приглашения в комнаты и управление участниками;
- push-уведомления;
- активные сессии и список устройств;
- административная панель;
- проверка состояния сервера через `/health`;
- автоматическая установка и обновление на Linux-сервере.

Для Android есть отдельный клиент: [ZhurMessengerApp](https://github.com/WWWorm92/ZhurMessengerApp).

## Стек

Backend написан на Node.js и Express. Для обмена событиями используется Socket.IO, данные хранятся в SQLite, а загруженные файлы — в отдельном каталоге на сервере.

Основные зависимости:

- Node.js;
- Express;
- Socket.IO;
- SQLite;
- JWT;
- bcrypt;
- Multer;
- Web Push.

В рабочей установке приложение обычно запускается как systemd-служба, а перед ним работает Nginx с HTTPS.

## Быстрый запуск

```bash
npm install
cp .env.example .env
npm start
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:3010
```

Порт, путь к базе, каталог загрузок и остальные параметры можно изменить в `.env`.

## Установка на сервер

В репозитории есть установочный скрипт для Debian/Ubuntu:

```bash
sudo bash scripts/install-anywhere.sh
```

Скрипт помогает:

- установить Node.js и необходимые пакеты;
- создать конфигурацию;
- настроить systemd-службу;
- подключить Nginx;
- выпустить HTTPS-сертификат;
- создать первого администратора.

Для установки автоматического обновления:

```bash
sudo bash scripts/install-auto-update.sh
```

Перед использованием скриптов на рабочем сервере рекомендую сначала просмотреть их и проверить значения переменных окружения.

## Что нужно сохранять при переносе

Главные данные находятся здесь:

```text
data/messenger.db
uploads/avatars
uploads/messages
```

Перед обновлением или переносом сервера сделайте резервную копию базы и каталога `uploads`.

## Проверка состояния

```http
GET /health
```

Пример ответа:

```json
{
  "ok": true,
  "uptime": 123,
  "users": 5,
  "env": "production"
}
```

## Основные настройки

Пример конфигурации находится в `.env.example`.

Чаще всего используются:

- `PORT` — порт приложения;
- `HOST` — адрес привязки;
- `JWT_SECRET` — секрет для токенов;
- `CORS_ORIGIN` — разрешённый адрес клиента;
- `DB_PATH` — путь к SQLite-базе;
- `UPLOADS_DIR` — каталог загруженных файлов;
- `HTTPS_KEY_PATH` и `HTTPS_CERT_PATH` — сертификат и ключ, если HTTPS завершается непосредственно в Node.js.

## Состояние проекта

Проект используется и продолжает развиваться, но пока не позиционируется как готовая корпоративная платформа. Перед публичным внедрением стоит отдельно проверить резервное копирование, ограничения загрузок, права доступа, защиту от перебора паролей и сценарии восстановления после сбоя.

Некоторые части кода появились в ходе решения практических задач, поэтому структура проекта постепенно приводится к более модульному виду.
